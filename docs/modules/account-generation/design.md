# 账号与遗器数据

状态：账号原始数据生成已实现。日期：2026-11-11。本文维护字段、推荐关系、资源指标与后续交付约定。当前账号接口支持金数、统一五星配装、推荐关联和集中分配，实际配置转换待实现。

## 数据流与职责

程序生成与玩家数据接入提供账号实际持有的原始配置。后续配置转换按角色 ID 补齐未持有角色的试用配置，并应用游戏规则，供模型和战斗侧使用。流程图、各模块的输入输出及映射职责见[账号数据流与模块职责](data-flow.md)。

开发样例、实验和训练记录通过“快照 ID + 条目类别 + 条目 ID”引用所用数据，支持后续复现。

原始账号记录持有的角色与装备实例。配置转换补齐试用并输出可用资源及使用限制；策略模块据此选择阵容、分配装备，环境检查操作是否合法。

## 原始配置保存什么

| 对象 | 首轮需要表达的内容 |
| --- | --- |
| 角色 | 持有角色的常规 ID、星魂数，以及转换所需的原始等级信息 |
| 行迹 | 普攻、战技、终结技和天赋的基础等级，以及已解锁的额外能力和属性节点 ID |
| 光锥 | 光锥 ID、叠影，以及转换所需的等级信息；可分配的光锥用实例 ID 区分 |
| 遗器实例 | 实例 ID、套装 ID、部位、品质、强化等级、主词条 ID、副词条属性 ID 与数值 |
| 装备关系 | 配置引用的光锥、遗器实例 ID，用于识别归属和检查重复占用 |
| 复现信息 | 配置 ID、格式版本、游戏数据快照、规则版本；生成样本另记生成器版本、参数和随机种子 |

当前原始角色与光锥均保存等级和突破阶段，表达突破边界上的不同配置。具体字段与调用方式见[完整角色配置生成](character-generation.md)。行迹记录基础等级，星魂附加等级由转换程序按规则处理。角色、光锥和套装的具体数值与机制通过 ID 查询对应数据。

角色在持有列表中缺席时，转换程序采用对应版本的试用配置。练度不足时，转换程序按[游戏规则](../../project/game-rules.md)应用默认配置，输出局内实际生效的等级、行迹、属性和机制引用。各字段的触发条件、默认值和替换范围先用实测样例核对，再进入规则数据。必需数据缺失时报告具体缺项。

同一种生效配置可以关联多份原始配置；训练时按映射后的差异采样，并保留资源约束。全试用任务由后续实际配置与挑战流程采用对应试用模板。

## 推荐配对与配装需求

账号生成使用常规游戏的推荐搭配模拟玩家抽卡与养成形成的资源关联。固定推荐关系随资料版本维护，生成请求控制关联强度，影响预算内角色和装备的选取概率。

角色配置从参考目录下的 `character/<角色 ID>.json` 读取下列字段。

| 字段 | 账号生成用途 |
| --- | --- |
| `teams` | 按原队伍与替补关系保存推荐角色，提高持有核心角色后选入关联角色的概率 |
| `lightcones` | 提供推荐光锥 ID 列表，作为光锥分配候选 |
| `relics.set4_id_list`、`set2_id_list` | 提供外圈套装和位面饰品候选 |
| `relics.property_list3`～`property_list6` | 提供躯干、脚、球、绳的主词条候选 |
| `relics.sub_affix_property_list` | 按原始顺序提供推荐副词条，映射为有效词条权重 |

推荐关系描述玩家的抽卡关联；货币战争中的阵容由策略使用实际账号资源选择。推荐队伍中的角色是否参与账号生成，由本次角色范围决定。

### 推荐副词条权重

按推荐列表的原始顺序，将属性适配为本项目统一键后赋权：

| 推荐位置 | 有效词条权重 |
| --- | ---: |
| 第 1 项 | 1 |
| 第 2 项 | 1 |
| 第 3 项 | 0.5 |
| 第 4 项及以后 | 0.3 |
| 未列出的属性 | 0 |

例如瓦尔特的推荐顺序为暴击率、暴击伤害、攻击%、速度、效果命中，对应：

```python
effective_stat_weights = {
    "CRIT Rate_": 1,
    "CRIT DMG_": 1,
    "ATK_": 0.5,
    "SPD": 0.3,
    "Effect Hit Rate_": 0.3,
}
```

这些权重乘以按单次中档数值折算的词条数，得到有效词条得分。不同角色可以对同一件遗器给出不同得分。

当前资料读取接口已将推荐属性适配为上述权重，完整角色生成默认采用推荐配装。单件与六件接口继续接收显式的 `effective_stat_weights`，调用方可按具体打法覆盖。

## 光锥持有与装备实例

账号以光锥 ID 表示种类，以实例 ID 表示可分配的装备。活动光锥和模拟宇宙光锥每种至多生成一个实例；其他光锥允许相同 ID 的多个实例，各自记录等级和叠影。

每个实例的叠影取 1～5。唯一实例限制按光锥种类统计，叠影等级记录在该实例上。同一实例的装备归属通过实例 ID 引用，用于处理同时占用；同 ID 的不同实例可以分别分配。

当前编号分类与唯一范围见[光锥编号分类与持有数量](../../game-data/light-cone-data.md#编号分类与持有数量)。资源预算和生成参数进一步约束允许生成的实例数量。

## 遗器怎样生成

当前支持五星 +15 单件与角色六件遗器的目标生成。部位、主词条与角色有效副词条由调用方指定；生成器直接分配合法的获得次数与档位数量，产生最终数值。六件套同时满足单件及合计目标，参数与调用方式见[角色六件遗器生成](character-relics.md)。

生成目标可以限制平均词条水平、属性倾向和角色之间的资源分布。生成后核对实际指标是否落在目标范围；约束无法满足时返回具体原因。普通搭配、合理搭配和有明显短板的搭配都保留样本，供不同训练阶段使用。

## 账号怎样评价与按条件生成

资源指标用于描述投入和控制生成条件，对局成绩用于估计账号在指定测试条件下的能力。第一版分别保存以下指标：

| 指标 | 统计约定 |
| --- | --- |
| 金数 | 持有的五星角色本体、星魂及五星光锥叠影按份数统计；限定每份 1 金、常驻每份 0.5 金，免费资源默认单列 |
| 遗器词条水平 | 记录成品副词条的最终数值。有效词条按指定角色或打法的权重，以单次中档数值折算 |
| 资源集中程度 | 记录各角色配置的投入分布，区分资源集中与分散的账号 |

遗器平均值同时注明统计范围，例如账号库存或选定角色的六件套。速度、充能等关键属性单独保留，支持后续检查阈值和搭配关系。账号生成采用前述推荐权重约定，调用方可按角色或打法显式提供权重；资源集中程度按核心人数混合平均与核心投入，并在容量饱和后继续分配，参数及实际份额见[账号接口](account-generation.md)。按角色分配遗器质量可采用[遗器练度五档设计](relic-quality.md)，再换算为现有生成接口的有效词条上下限。

按条件生成账号时，可指定金数、全 01／全 21 等统一五星配装、遗器指标范围、候选角色及资源分布，再分配星魂、光锥和遗器。原始账号记录实际资源指标，交由后续配置转换生成生效配置。模型主要练习映射后仍有差异的配置。

模拟接通后，在固定场景、策略和计算预算下报告通关率、SSS 率及不同打法的表现，并附样本量。模型更新时记录评价策略版本，便于区分策略改进和账号资源差异。训练与评估按账号配置及整局划分，保留未参与训练的账号和组合。

## 首个样例与完成条件

当前先交付一个角色、一个光锥和六件遗器的输入输出样例：

1. 从已有游戏资料中选择条目，记录数据快照、规则依据和待核对字段。
2. 写出原始配置与装备实例，明确 ID、单位、等级及行迹的口径。
3. 给出固定种子的遗器生成参数、生成结果和资源指标。
4. 给出该配置按游戏规则转换后的预期结果，覆盖练度不足的映射情况和实际试用配置。
5. 与战斗侧核对生效配置的读取方式，与运营侧核对可用资源、装备关系及合法操作所需字段。

完成时应能复现遗器结果，检查主副词条及强化是否合法，并追溯生效配置使用的规则。账号数据任务可先核对转换结果；战斗和运营接入后，再分别补充数值对照与节点联调结果。具体任务安排见[实施阶段与任务拆解](../../project/roadmap.md)。
